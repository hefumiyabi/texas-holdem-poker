# 人格牌局设计规格

## 目标

把现代 React 版本重做为“单人挑战机器人”优先的手机网页版。用户输入昵称后可一键创建练习桌，选择机器人难度与阵容，并在不滚动的牌桌中完成整手牌；邀请好友保留为次级入口。

## 核心体验

主路径为：

`输入昵称 → 选择难度/机器人阵容 → 一键开局 → 完成一手 → 查看简短复盘 → 下一手`

牌桌空座可以添加机器人或邀请好友。邀请链接加入的真人只能在两手之间入座或替换机器人，进行中的牌局不换座。

## 机器人设计

公开产品只提供公平机器人，任何难度都不能读取对手底牌。现有 `GOD` 策略仅保留为开发测试能力，不出现在 UI 或公开 Socket 接口中。

难度分三档：

- 休闲：使用基础牌力、位置和底池赔率；较少诈唬；允许受控的次优选择。
- 常规：加入范围意识、下注尺度、半诈唬和有限对手建模。
- 高手：使用近似 GTO 的混合频率、SPR、阻断牌启发式、价值/诈唬组合及跨手对手建模。

人格与难度正交。首版提供五种人格：

- `balanced` 理性哥：稳健均衡，混合尺度。
- `aggressive` 深海鱼：高进攻频率，敢三枪诈唬。
- `tight` 冷静先生：范围紧，价值下注明确。
- `caller` 小雨：入池宽、跟注多、诈唬少。
- `tricky` 玫瑰：慢打和极化下注更多，难以读取。

机器人通过受控随机源选择策略分支。同一输入与 seed 必须可复现，便于测试；随机性不能产生非法动作。机器人只暴露人格标签、难度和思考状态，不暴露胜率或决策理由。

## 牌桌 UI

- 目标视口为 `390×844`，活动牌局不得产生页面纵向滚动。
- 温暖的私人牌局氛围：炭黑背景、墨绿绒面、奶油白牌面和铜金强调色。
- 五个机器人座位沿桌边分布，显示头像、昵称、筹码和一个人格标签。
- 当前行动者有圆形倒计时；机器人行动时显示“思考中”。每手最多出现一条克制的桌边反应。
- 公共牌、底池和下注额居中；自己的两张底牌靠近底部并放大。
- 底部固定三个主要动作：`弃牌`、`跟注/过牌`、`加注/下注`。只有合法动作可用。
- 点击加注后在按钮上方展开滑杆与 `½池 / ¾池 / 满池 / 全下`，不得遮住底牌或公共牌。
- 顶部只保留菜单、难度/对手阵容和邀请好友。移除常驻底部工具导航。
- 所有触控目标至少 44px，核心文字满足 WCAG AA，支持键盘焦点和减少动态效果。

## 入口与阵容

首页主操作为“挑战机器人”。阵容选择使用一个底部抽屉，提供：

- 难度：休闲、常规、高手。
- 人数：单挑、四人桌、六人桌。
- 阵容：自动搭配或逐个选择人格。
- 买入：使用现有房间初始筹码，首版不提供真钱或充值。

创建房间后由服务端一次性添加阵容，避免客户端连续点击造成重复机器人。牌桌等待阶段仍可点击空座调整机器人；只有房主可修改阵容。

## 数据与接口

- `POST /api/v1/rooms` 接受可选练习配置：`mode: "bot_challenge"`、`difficulty`、`seat_count`、`personas`。
- `bot:add` 接受 `level` 和 `persona`，服务端校验枚举、房主权限、房间状态和空座。
- 快照中的机器人新增 `bot_level`、`bot_persona`、`persona_label`；不发送隐藏策略数据。
- 现有邀请链接、游客会话、房间码、断线恢复和扑克结算继续作为权威后端能力。

## 非目标

首版不实现实时 CFR 求解器、排行榜、公开匹配、商城、聊天、语音、真实货币或自动学习模型。GTO 是可测试的近似策略层，不宣传为完整求解器。

## 验收标准

- 三个公开难度均不会读取其他玩家底牌，`GOD` 不可由公开接口创建。
- 机器人在固定 seed 下动作可复现，且随机长局无非法动作、卡死或筹码不守恒。
- 用户可在 3 次点击内从首页开始六人机器人牌局。
- `390×844` 中牌桌、手牌和操作按钮同时可见且不滚动。
- 空座可添加指定人格机器人或复制好友邀请链接。
- React、Python、构建、核心浏览器交互与设计 QA 全部通过。
