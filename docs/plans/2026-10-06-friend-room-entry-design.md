# 好友房入口与玩家筹码可见性设计

## 目标

在现有单人挑战首页补齐明确的好友房流程，并保证牌桌上的真人玩家始终能看见自己的筹码。

核心路径：

`首页 → 创建好友房 → 选择人数与带入 → 获得房间码和邀请链接 → 分享 → 进入牌桌等待好友`

## 首页与创建流程

- 首页保留“挑战机器人”。
- 新增独立的“创建好友房”主入口。
- “输入房间码加入”继续保留，首页形成三个清晰入口。
- 创建好友房使用独立弹窗，不展示机器人难度或机器人性格。
- 可选牌桌人数为 2、4、6 人。
- 可选带入金额为 1,000、5,000、10,000。
- 创建期间禁用重复提交，并在弹窗内展示接口错误。

## 邀请与进入牌桌

- 创建成功后，弹窗切换到邀请确认状态，展示六位房间码。
- 提供“复制邀请链接”和“系统分享”两个操作。
- 提供“进入牌桌”按钮，由房主主动进入等待状态。
- 牌桌顶部继续保留现有“邀请好友”入口，便于再次分享。
- 好友通过 `/room/:code` 进入现有预览和加入流程。
- 好友房等待阶段继续允许房主在空位补机器人。

## 自己的筹码

- 真人玩家的昵称和筹码显示在手牌上方的专用信息条中。
- 信息条与手牌、底部操作栏共享明确的安全间距，在手机竖屏和矮横屏上均不可互相遮挡。
- 普通座位标签仍用于其他玩家；自己的专用信息条是筹码显示的权威视觉位置。
- 筹码变化直接来自服务器快照，不在前端自行计算。

## 数据与接口

- 复用现有 `POST /api/v1/rooms`，提交 `max_players` 与 `initial_chips`。
- 后端继续生成私密六位房间码和 `invite_url`。
- 前端增加专用好友房创建参数类型，避免与机器人挑战参数混用。
- 不新增公开匹配、账号、聊天或真实货币功能。

## 测试与验收

- 组件测试覆盖首页好友房入口、人数与带入选择、创建参数、创建成功后的房间码、复制/分享及进入牌桌。
- API 测试确认普通好友房接受并保存三个允许的带入金额，拒绝越界值。
- 牌桌测试确认自己的昵称和筹码来自当前 viewer。
- 在 390×844、1440×686 和 1440×900 下验证筹码、手牌与操作栏互不遮挡。
- 运行完整前端测试、后端测试和生产构建后再部署 Render。
