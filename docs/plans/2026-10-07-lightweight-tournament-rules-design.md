# 轻量锦标赛规则设计

日期：2026-10-07

## 目标与约束

在现有 Flask、Socket.IO、React 和 SQLite 架构内，为机器人挑战与好友私人局统一增加更完整的锦标赛体验：严格行动顺序、点击式下注、真人重买、淘汰选择、净输赢结算、按时间升级盲注和一小时断线保留。

继续使用现有 Render Free 单实例，不增加付费服务器、Redis 或 PostgreSQL。全部功能先在本地实现和验收；未经用户明确确认，不推送 GitHub 或部署 Render。

Render Free 在连续 15 分钟没有 HTTP 请求或 WebSocket 消息时可能休眠，休眠、重启或重新部署会丢失本地 SQLite 和内存状态。因此本设计只保证服务仍存活时的一小时断线恢复，不承诺实例休眠或重启后的牌局恢复。

## 方案选择

采用增量升级现有扑克引擎。保留已经验证的发牌、比牌、边池、平分和筹码守恒逻辑，在现有 `Table` 与房间快照上扩展锦标赛状态。相比另建锦标赛引擎或全面事件溯源重写，这一方案改动更小，也更适合当前单实例资源限制。

## 严格行动顺序

- 服务端是唯一行动顺序权威，只接受 `current_player_id` 对应玩家的命令。
- 牌桌维护递增的行动版本。当前玩家、街道或手牌发生变化时版本递增。
- 机器人思考前记录手牌编号、街道、当前玩家和行动版本；提交前在牌桌锁内再次校验，任一字段变化即丢弃旧决定。
- 真人行动与机器人提交都经过同一张牌桌的状态锁。
- 机器人循环遇到真人回合立即停止。真人未行动、当前真人断线或牌桌暂停时，不允许后位机器人提前行动。
- 真人没有行动倒计时，不自动过牌或弃牌。只有主动行动、主动退出或断线保留期结束后，牌局才能继续。

## 点击式下注

移除下注滑杆，改用两行金额按钮与自定义输入：

- `½池`
- `¾池`
- `满池`
- `3×`
- `4×`
- `6×`
- `全下`
- `自定义`

无人下注时，池比例按当前底池计算。面对下注时，池比例按跟注后的底池计算合法加注目标；`3× / 4× / 6×`按当前最高下注额计算。无人加注的翻牌前场景中，当前最高下注即大盲。

每个按钮同时显示最终目标金额。所有金额在客户端用于预览，但最终由服务端限制到合法最小下注或加注与玩家全下金额之间。自定义金额必须二次确认。

## 淘汰、观战和重买

- 机器人挑战和好友房都采用锦标赛状态。
- 房间可设置每位真人的重买次数：0、1、2、3 或无限；默认 1 次。
- 只有筹码归零、且牌局处于两手之间的真人可以重买。
- 重买恢复到房间起始筹码，并原子地增加已使用次数，防止重复请求获得多份筹码。
- 真人筹码归零后显示 `重新买入 / 继续观看 / 退出牌桌`。
- 选择观战后仍可在以后两手之间重买，直到额度用完。
- 主动退出立即离开，不受断线保留规则影响。
- 机器人永远不能重买；筹码归零后直接淘汰。

## 盲注时钟

- 第一手开始时启动锦标赛有效时间。
- 默认每 10 分钟升级一级，不向用户增加额外的速度设置。
- 采用循环平滑倍率：`[1, 1.5, 2, 3, 4, 5, 7.5] × 10ⁿ`，即 `1× → 1.5× → 2× → 3× → 4× → 5× → 7.5× → 10× → 15× → 20×…`。
- 自定义盲注乘法结果按整数四舍五入（0.5 向上），并强制大盲始终大于小盲。
- 例如基础盲注为 `10/20` 时，前八级为 `10/20 → 15/30 → 20/40 → 30/60 → 40/80 → 50/100 → 75/150 → 100/200`。
- 时间到达时不改变正在进行的手牌，只在下一手开始时应用新级别。
- 当前真人断线导致牌桌暂停时，锦标赛有效时间也暂停；非当前真人断线不改变游戏身份，轮到他时才暂停，因此机器人不能跳过其座位。重连后继续累计。
- 后端不运行每秒任务。通过时间锚点和累计有效秒数，在开始新手、行动、断线及重连时惰性计算当前等级。

## 每手结算

发牌前记录每位参赛者的起始筹码。结算后服务端生成隐私安全的结果：

- 起始筹码
- 本手实际投入
- 收到的底池份额
- 净输赢
- 结束筹码
- 获胜牌型与原因
- 所有参与玩家的输赢明细

净输赢以结束筹码减起始筹码计算，因此能够自然覆盖边池、平分和未被跟注筹码退回。前端不自行推导金额。

结算卡默认显示自己的净输赢、底池分配和最终筹码，可展开查看所有玩家及牌型。卡片必须避开公共牌、自己的手牌和底部操作区。

## 一小时待机与恢复

- 浏览器保持连接但没有操作时不退出牌局。
- 打开牌桌的客户端每 5 分钟发送极小的房间心跳。
- 被动断线后保留房间成员关系、座位、筹码、参赛或观战状态 60 分钟。
- 当前行动真人断线时冻结牌局和盲注有效时间。
- 60 分钟内使用相同游客会话重连，自动恢复原位置和状态。
- 超过 60 分钟仍未重连时，本手按弃牌处理并转为观战；不立即删除玩家资料。
- 清理采用断线时间戳和定期惰性扫描，不为每位玩家创建持续一小时的后台睡眠线程。
- Render Free 实例完全休眠或重启后的状态恢复不在保证范围内。

## 数据与接口

房间增加：真人重买上限、盲注级别时长、累计有效比赛秒数、时钟锚点、当前盲注等级和暂停状态。

房间玩家增加：已使用重买次数、锦标赛状态和断线时间。无限重买使用明确的枚举或空值表达，不依赖前端约定的任意大整数。

Socket 增加或扩展：

- `room:heartbeat`：刷新连接活动状态。
- `player:rebuy`：服务端验证后重买。
- `player:spectate`：转为观战。
- `player:act`：携带行动版本，拒绝陈旧或重复动作。
- 快照公开当前盲注、下一盲注、剩余时间、暂停状态、真人重买额度和自己的已用次数。

机器人挑战和好友房创建接口都接收真人重买上限。机器人创建逻辑不接收重买额度。

## 轻量化策略

- 保持单 Gunicorn worker 和线程模式。
- 盲注、断线和重买均使用事件驱动的惰性计算。
- GTO 胜率只在真人回合计算并复用现有缓存。
- 机器人只在成为当前玩家后计算一次，状态改变后不重算旧决定。
- 不新增持续轮询、不保存完整事件日志、不引入外部消息系统。
- 若负载测试显示 CPU 压力过高，优先减少 GTO 蒙特卡洛样本数，而不删除规则、结算或权限校验。

## 错误处理

- 非当前玩家、错误行动版本或重复行动均被拒绝，且不改变筹码和牌桌状态。
- 非法金额由服务端拒绝或按已定义规则裁剪，客户端显示服务端确认的目标金额。
- 机器人重买始终被拒绝。
- 非破产真人、手牌进行中或额度已用完时拒绝重买。
- 重连和重买均需幂等，不能重复发放筹码或重复消耗额度。
- 盲注到点时不得改变当前手牌的下注规则。
- 所有结算继续满足筹码守恒。

## 测试与验收

- 使用虚拟时钟测试 10 分钟盲注和 60 分钟断线，不真实等待。
- 覆盖两人、四人和六人桌翻牌前及翻牌后的行动顺序。
- 模拟真人停顿，证明后位机器人不会行动。
- 模拟机器人思考期间状态变化，证明旧决定被丢弃。
- 覆盖全部下注快捷键、跟注后底池公式、最小加注和全下边界。
- 覆盖真人重买 0、1、2、3、无限以及机器人禁止重买。
- 覆盖胜负、弃牌、平分和边池的净输赢结算。
- 验证刷新、短暂断网、60 分钟恢复、观战和主动退出。
- 保持现有规则、机器人、API 和前端测试全部通过。
- 在手机视口验证下注按钮、结算卡和淘汰选择不遮挡牌面。
- 使用两个浏览器上下文验证严格顺序和重连。
- 本地完成 10 个房间、60 条 Socket 连接的轻量冒烟测试。
- 完成后只提供本地地址供用户确认；收到明确推送许可前不推送或部署。
